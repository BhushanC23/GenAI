## 3. Project brief — KubeCoach

### Problem
Students learning Kubernetes often find official documentation dense. They need clear explanations of Kubernetes concepts, commands, relationships between objects, and reliable source links.

### Intended user
A final-year IT student preparing for a DevOps internship/interview and practising Kubernetes using Minikube.

### Product goal
Explain Kubernetes objects and `kubectl` commands in plain English, using official Kubernetes documentation as the knowledge source. Answers should be grounded, cite sources, and admit when the available context is insufficient.

### Data sources
- Official docs: `https://kubernetes.io/docs/concepts/`
- Official website source tree: `https://raw.githubusercontent.com/kubernetes/website/main/content/en/docs/concepts`

Use official sources as the default. Do not fabricate documentation, citations, Kubernetes behavior, commands, defaults, or limits. Keep a source URL with each ingested record/chunk.

### Structured record fields
Each knowledge record should retain as applicable:
- `page_title`
- `category`
- `one_line_definition`
- `key_kubectl_command`
- `limit_or_default`
- `source_url`

Additional metadata can be introduced only when useful and documented (for example chunk ID, heading, content, or source page).

### Product requirements that become explicit later
- Search Kubernetes knowledge.
- Return answers supported by retrieved source context.
- Include citations/source URLs that correspond to actual retrieved chunks.
- Handle unanswerable questions honestly (“I don't know” / insufficient context).
- Explain Kubernetes object relationships, such as `Deployment → ReplicaSet → Pods ← Service`, when supported by the answer/context.
- Provide a deterministic Kubernetes quantity converter.
- Include a UI for demonstrations and feedback.
- Add tests, evaluation, and deployment/portfolio documentation as assigned.

### Signature feature: Object Relationship Strip
Example:
`Deployment → ReplicaSet → Pods ← Service`

The relationship visualization must be grounded in verified Kubernetes relationships. Do not present an arbitrary or unsupported graph as fact. A curated mapping can be used if it is checked against official documentation and clearly scoped.

### Signature tool: `k8s_quantity_converter`
A deterministic utility for Kubernetes CPU/memory quantities and comparisons. Required examples:
- `500m` CPU = `0.5` CPU
- `1000m` CPU = `1` CPU
- `512Mi` = 512 MiB
- `1Gi` = 1024 MiB

Respect decimal SI and binary IEC units; do not conflate them. Validate input and return understandable errors. Do not rely on an LLM to perform arithmetic.
